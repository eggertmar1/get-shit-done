1. **Detection Logic** - How to determine if repo uses flat vs nested structure:
   - Check if `.planning/projects/` directory exists
   - If exists: nested structure (read .active file)
   - If not exists: flat structure (direct paths)

2. **Resolution Algorithm** (pseudocode in markdown):
   ```
   function resolvePlanningPath(relativePath):
     planningRoot = cwd + '/.planning'

     # Shared paths always at root
     if relativePath starts with 'codebase/' or equals 'config.json':
       return planningRoot + '/' + relativePath

     # Check structure type
     if exists(planningRoot + '/projects/'):
       # Nested structure - need active project
       activeFile = planningRoot + '/.active'
       if not exists(activeFile):
         throw NO_ACTIVE_PROJECT
       activeProject = read(activeFile).trim()
       if empty(activeProject):
         throw EMPTY_ACTIVE_FILE
       projectDir = planningRoot + '/projects/' + activeProject
       if not exists(projectDir):
         throw PROJECT_NOT_FOUND(activeProject)
       return projectDir + '/' + relativePath
     else:
       # Flat structure - direct path
       return planningRoot + '/' + relativePath
   ```

3. **Error Handling** (from CONTEXT.md locked decisions):
   - NO_ACTIVE_PROJECT: Prompt user to select from available projects
   - EMPTY_ACTIVE_FILE: Same as NO_ACTIVE_PROJECT
   - PROJECT_NOT_FOUND: Prompt user to select from available projects

4. **Usage Pattern** for commands/agents:
   ```markdown
   # In command/agent <process> section:

   1. Resolve paths using path-resolution algorithm
   2. When reading PROJECT.md:
      projectPath = resolvePlanningPath('PROJECT.md')
   3. When writing STATE.md:
      statePath = resolvePlanningPath('STATE.md')
   ```

5. **Transition Period** behavior:
   - Flat structure: All paths work as before (no change needed)
   - Nested structure: All project paths route through active project
   - Mixed state: Should never happen (migration is atomic per repo)

Follow the format of existing references like `git-integration.md` (heading structure, code examples, when-to-use patterns).
